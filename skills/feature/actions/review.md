# Review the feature

1. Read the active spec, the domain rules and review priorities in `context/project-overview.md`, and the shared coding standards.
2. Inspect the full work branch diff since divergence from `dev`, including committed, staged, unstaged, and relevant untracked changes.
3. Check acceptance criteria, scope, behavior for existing callers and data, security boundaries, and test coverage. For UI work, check relevant states and representative viewports when possible. Consider applicable screenshots for visual direction and use the spec and existing design system to assess behavior and usability.
4. Report findings in order of impact. Include the affected file or behavior, consequences, and supporting evidence. List checks run and any criteria still unverified.
